Mini RAG App Documentation

Introduction

This document provides detailed documentation for the Mini RAG App, a minimal implementation of the Retrieval-Augmented Generation (RAG) model for question answering. The application is built with FastAPI and uses MongoDB for data storage.

Project Structure

The project is organized into the following main directories:

  • src/: Contains the main source code for the application.
  • src/controllers/: Handles the business logic of the application.
  • src/models/: Manages data models and database interactions.
  • src/routes/: Defines the API endpoints.
  • docker/: Includes Docker-related files for setting up the environment.

API Endpoints

GET /api/v1/

Description: Retrieves the application name and version.

Responses:

{
    "app_name": "mini-rag",
    "version": "1.0.0"
}

POST /api/v1/data/upload/{project_id}

Description: Uploads a file to the specified project.

Parameters:

  • project_id (path, required): The ID of the project to upload the file to.
  • file (form data, required): The file to upload.

Responses:

{
    "signal": "file_uploaded_success",
    "asset_id": "668f8f8f8f8f8f8f8f8f8f8f",
    "file_id_name": "randomstring_filename.pdf"
}

POST /api/v1/data/process/{project_id}

Description: Processes the files in a project by splitting them into chunks.

Parameters:

  • project_id (path, required): The ID of the project to process.
  • file_id (body, optional): The ID of a specific file to process.
  • chunk_size (body, optional): The size of the chunks to split the file into. Default is 100.
  • overlap_size (body, optional): The size of the overlap between chunks. Default is 20.
  • do_reset (body, optional): If set to 1, all existing chunks for the project will be deleted before processing. Default is 0.

Responses:

{
    "signal": "processing_success",
    "inserted_chunks": 150,
    "processed_files": 3
}

Controllers

DataController

validate_uploaded_file(file: UploadFile)

Validates the uploaded file based on its type and size.

generate_unique_filepath(original_file_name, project_id: str)

Generates a unique file path for the uploaded file.

get_clean_file_name(original_file_name: str)

Cleans the original file name by removing special characters and replacing spaces with underscores.

ProcessController

get_file_extension(file_id: str)

Returns the file extension of the given file ID.

get_file_loader(file_id: str)

Returns the appropriate file loader for the given file ID.

get_file_content(file_id: str)

Loads the content of the file using the appropriate loader.

process_file_content(file_content: list, file_id: str, chunk_size: int=100, overlap_size: int=20)

Processes the file content by splitting it into chunks.

ProjectController

get_project_path(project_id: str)

Returns the path to the project directory, creating it if it does not exist.

Models

AssetModel

create_asset(asset: Asset)

Inserts a new asset into the collection.

get_all_project_assets(asset_project_id: str, asset_type: str)

Retrieves all assets for a given project and asset type.

get_asset_record(asset_project_id: str, asset_name: str)

Retrieves a specific asset record by project ID and asset name.

ChunkModel

create_chunk(chunk: Data_Chunk)

Inserts a new chunk into the database.

get_chunk(chunk_id: str)

Retrieves a chunk by its ID.

insert_many_chunks(chunks: list, batch_size: int=200)

Inserts multiple chunks into the database in batches.

delete_chunks_by_project_id(project_id: ObjectId)

Deletes all chunks associated with a specific project ID.

ProjectModel

create_project(project: Project)

Creates a new project.

get_project_or_create_one(project_id: str)

Retrieves a project by its ID or creates a new one if it doesn't exist.

get_all_projects(page: int=1, page_size: int=10)

Retrieves a paginated list of all projects.
